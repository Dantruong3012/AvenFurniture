# One-command development launcher

Run `npm run ai:auto` from the configured development branch and a clean checkout. The launcher reads `.env.local` through Node's `--env-file`, checks Git, all worktrees, the approved backlog, current checkpoint and the shared lock, then runs the existing coordinator. A successful first run must complete the real Antigravity → Codex → Antigravity → Codex smoke test in a temporary Git repository before touching a backlog task. The smoke receipt is tied to the launcher/runner file digest; a changed runner requires another smoke test. Normal task progress, tests, review and commits remain the existing coordinator's responsibility.

`npm run ai:auto -- --check` performs read-only preflight and prints JSON status. `npm run ai:auto -- --smoke` runs only the isolated real-CLI proof. Both commands use the same `.env.local` entry point. When a quota receipt exists, the launcher does not retry before the reported reset. `--smoke --quota-ready` is only for an operator who has independently confirmed the CLI is available earlier. A failed smoke retains its failure receipt and blocks unattended retries.

The launcher stops on a BLOCKED task/checkpoint, stale lock, dirty working tree for a new task, wrong branch, unresolved dependency or unapproved roadmap. A resumed task's working changes are checked by the coordinator against its saved ownership. The launcher also stops when a privileged token/key is present in `.env.local`, since an agent with workspace read access could read the file even after its process environment is filtered. Move management credentials to a protected environment outside the agent workspace and retain only safe application variables in `.env.local` before activating unattended task execution. It does not change the current `admin-inquiry-portal` checkpoint or treat a task on another worktree as completed. Ctrl+C reaches the coordinator stop handler, which preserves its checkpoint. The next normal invocation resumes a safe `STOPPED` task; quota resume waits for its saved reset time. A `BLOCKED` architecture decision needs a revised approved plan and supported recovery, never an automatic clearance.

Preflight uses read-only Vercel project, Supabase project-list and GitHub branch endpoints. It reports only HTTP statuses, exact project matches and branch protection, never tokens or response bodies. The coordinator keeps management tokens for its fixed adapters, while model-driven Antigravity/Codex subprocesses receive a filtered environment. Private process logs redact known environment secret values. This is a defense in depth measure; provider tokens in a local file still need least-privilege account policy. The launcher contains no provider billing/write API route.

The release module remains disabled/manual. A successful local task commit is not a completed Preview/CI/Production release. M2–M8 adapters and live checks require separate review. GitHub main currently has no branch protection, and there is no authenticated GitHub API identity in this environment. The actual dev branch also has an unresolved admin checkpoint. Consequently the one-command task loop is implemented, but unattended execution of the current backlog must remain blocked until the approved admin plan is made compatible with the existing inquiry status constraint and recovery is reviewed. Do not run the entire backlog as a setup test.

The coordinator now keeps a real Markdown recovery note at `.ai-collab/.runtime/HANDOFF.md`. It rewrites the note after each lifecycle transition, when a completed CLI turn crosses the conservative warning threshold (32,000 input, 8,000 output, or 40,000 total tokens), and when a turn stops, blocks, or reports quota exhaustion. It records the task, phase, branch, HEAD, changed path names, receipt filenames, last reported CLI token usage, and the safe next action. It never copies raw model output, prompts, credentials, or an unverified approval into the note. `orchestrator.mjs status` shows the last usage and the note's path. These per-turn numbers do **not** reveal the account's remaining provider quota or the model's exact remaining context. A real 429 still creates `PAUSED_QUOTA` without retry; a context-limit error blocks with a handoff so the plan/context can be reduced before recovery.

Antigravity Planning and Review run from a new empty temporary directory while receiving only bounded task context and an absolute JSON schema. This prevents automatic repository discovery from consuming context or requiring a headless shell permission. Sandbox mode and strict checks for structured output and denied actions remain in place. Codex implementation still runs in the scoped task checkout so it can edit owned files.

Planning uses low CLI effort and Review uses medium effort to keep bounded tasks from consuming excessive reasoning tokens. If Antigravity reports an interrupted response stream, the coordinator disregards even a partial `APPROVED` payload, verifies that Git/source stayed unchanged, and retries that read-only turn once after a two-second delay with a new sequence. A second interruption blocks the task and writes the handoff. Quota exhaustion never enters this transient retry path.

Local, Preview and Production use the same Supabase database. This launcher never runs database migrations, reset/truncate/delete operations, or live E2E writes. SQL changes may be authored in source and tested in disposable local infrastructure. The missing `submit_customer_inquiry` RPC requires separate user approval before any Production application.
