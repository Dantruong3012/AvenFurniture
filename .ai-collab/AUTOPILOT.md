# One-command development launcher

Run `npm run ai:auto` from the configured development branch. A fresh task needs a clean checkout; a stopped task may keep task-owned working changes that the coordinator validates before any CLI call. The launcher reads `.env.local` through Node's `--env-file`, checks Git, all worktrees, the approved backlog, current checkpoint and the shared lock, then runs the existing coordinator. A successful first run must complete the real Antigravity → Codex → Antigravity → Codex smoke test in a temporary Git repository before touching a backlog task. The smoke receipt is tied to the launcher/runner file digest; a changed runner requires another smoke test. Normal task progress, tests, review and commits remain the existing coordinator's responsibility.

`npm run ai:auto -- --check` performs read-only preflight and prints JSON status. `npm run ai:auto -- --smoke` runs only the isolated real-CLI proof. Both commands use the same `.env.local` entry point. When a quota receipt exists, the launcher does not retry before the reported reset. `--smoke --quota-ready` is only for an operator who has independently confirmed the CLI is available earlier. A failed smoke retains its failure receipt and blocks unattended retries.

When the current task is `PAUSED_QUOTA`, independently verify that the affected CLI works, then run `npm run ai:auto -- run --quota-ready` to resume that exact task. Without the flag, `npm run ai:auto` remains paused when the reset time is unknown or still in the future. The launcher still checks the branch, remote, credential file, coordinator lock and real two-CLI smoke before passing `resume --quota-ready` to the coordinator; the coordinator independently validates the saved checkpoint and source ownership. Another quota failure pauses the task again.

A successful real-CLI smoke recorded after the quota error is recovery proof for the **same runner digest**, even before `retryAt`. The launcher compares the proof's `verifiedAt` with the quota receipt's `observedAt`; missing/invalid timestamps or a changed digest do not infer recovery. The old quota receipt stays on disk as history. A later 429 records a newer receipt and pauses again. This rule concerns the launcher smoke receipt only; it does not clear or rewrite a task checkpoint marked `PAUSED_QUOTA` or `BLOCKED`.

The launcher stops on a BLOCKED task/checkpoint, stale lock, dirty working tree for a new task, wrong branch, unresolved dependency or unapproved roadmap. A `STOPPED` or `RUNNING` checkpoint may have task-owned working changes; the launcher returns `RESUME` and the coordinator validates every changed path against the saved baseline and exact ownership before any CLI runs. An unknown checkpoint status remains blocked. The launcher also stops when a privileged token/key is present in `.env.local`, since an agent with workspace read access could read the file even after its process environment is filtered. Move management credentials to a protected environment outside the agent workspace and retain only safe application variables in `.env.local` before activating unattended task execution. Ctrl+C reaches the coordinator stop handler, which preserves its checkpoint. The next normal invocation resumes a safe `STOPPED` task; quota resume waits for its saved reset time. A `BLOCKED` architecture decision needs a revised approved plan and supported recovery, never an automatic clearance.

Preflight uses read-only Vercel project, Supabase project-specific and GitHub branch endpoints. It reports only HTTP statuses, exact project matches and branch protection, never tokens or response bodies. The coordinator keeps management tokens for its fixed adapters, while model-driven Antigravity/Codex subprocesses receive a filtered environment. Private process logs redact known environment secret values. This is a defense in depth measure; provider tokens in a local file still need least-privilege account policy. The launcher contains no provider billing/write API route.

Preview, merge and Production release remain disabled/manual. The independent development push gate runs only after verified review, checks and commits; it records the exact remote SHA before another task starts. A successful push is not Preview/CI/Production verification. M4–M6 adapters exist, while PR/CI-to-Production orchestration and live Preview E2E remain incomplete. The launcher reads scoped management credentials from the protected file outside the checkout and filters them from model-driven subprocesses. `.env.local` contains only public/non-sensitive application variables.

The current task and checkpoint are reported by `node .ai-collab/orchestrator.mjs status`; this document is not a live task pointer. A real two-CLI smoke fixture proves the Plan → Implement/Test → Review → Commit handoff for the exact runner digest recorded in `.runtime/autopilot-smoke.json`. A later runner change requires a new smoke. The one-command task loop is ready for unattended use only when `npm run ai:auto -- --check` reports `RUN` or `RESUME` and no credential or task blocker; the smoke alone is not permission to bypass a blocked checkpoint. `COMPLETE` means the approved backlog has no remaining task to implement.

The coordinator classifies Codex CLI usage-limit failures separately from implementation errors. It pauses the same phase with partial task-owned source preserved. If the CLI reports only a local clock time without date/timezone, the reset time stays unknown and unattended retry is blocked until an operator verifies Codex CLI availability and supplies `--quota-ready`. The legacy consultant checkpoint was recovered through the reviewed `recover-codex-quota` command and then completed; the launcher never clears a `BLOCKED` checkpoint automatically.

The coordinator now keeps a real Markdown recovery note at `.ai-collab/.runtime/HANDOFF.md`. It rewrites the note after each lifecycle transition, when a completed CLI turn crosses the conservative warning threshold (32,000 input, 8,000 output, or 40,000 total tokens), and when a turn stops, blocks, or reports quota exhaustion. It records the task, phase, branch, HEAD, changed path names, receipt filenames, last reported CLI token usage, and the safe next action. It never copies raw model output, prompts, credentials, or an unverified approval into the note. `orchestrator.mjs status` shows the last usage and the note's path. These per-turn numbers do **not** reveal the account's remaining provider quota or the model's exact remaining context. A real 429 still creates `PAUSED_QUOTA` without retry; a context-limit error blocks with a handoff so the plan/context can be reduced before recovery.

Task handoffs are persisted as compact `IMPLEMENTATION_BRIEF.md`, `IMPLEMENTATION_SUMMARY.md`, `VERIFY_REPORT.md`, and `REWORK.md` documents. Full check output remains in private `.runtime` logs; only deduplicated failure excerpts and log references enter review context. Telemetry also records cached input tokens, tool calls, shell output bytes, and duration in `.runtime/telemetry.json`, with configurable phase budgets in `orchestrator.config.json`. When deterministic commit is enabled, a real Antigravity approval and passing coordinator checks authorize the fixed local Git executor; no Codex commit turn is used.

Antigravity Planning and Review run from a new empty temporary directory while receiving only bounded task context and an absolute JSON schema. This prevents automatic repository discovery from consuming context or requiring a headless shell permission. Sandbox mode and strict checks for structured output and denied actions remain in place. Codex implementation still runs in the scoped task checkout so it can edit owned files.

Planning uses low CLI effort and Review uses medium effort to keep bounded tasks from consuming excessive reasoning tokens. If Antigravity reports an interrupted response stream, the coordinator disregards even a partial `APPROVED` payload, verifies that Git/source stayed unchanged, and retries that read-only turn once after a two-second delay with a new sequence. A second interruption blocks the task and writes the handoff. Quota exhaustion never enters this transient retry path.

Local, Preview and Production use the same Supabase database. This launcher never runs database migrations, reset/truncate/delete operations, or live E2E writes. SQL changes may be authored in source and tested in disposable local infrastructure. The missing `submit_customer_inquiry` RPC requires separate user approval before any Production application.
